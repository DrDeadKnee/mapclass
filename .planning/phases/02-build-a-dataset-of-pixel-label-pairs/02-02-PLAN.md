<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LUNA / Allmaps / IIIF servers → pipeline | Untrusted third-party HTTP responses (JSON + binary image) |
| Remote JPEG → Pillow/rasterio decode | Untrusted image bytes parsed locally |
| LUNA item id → output filename | Externally-derived string used in a filesystem path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02 | Tampering | LUNA item id → `<id>__plate<i>/` directory name | mitigate | Sanitize: replace any non-`[\w-]` char with `_` before path join (Task 2). LUNA ids are tilde-delimited, no `/` or `..`, but sanitize regardless |
| T-02-04 | Denial of Service | Oversized IIIF response (server ignores `!4096,4096`) exhausting memory/disk | mitigate | `iiif.fetch_iiif_image` checks `Content-Length`; abort if > 200 MB before decoding (Task 1) |
| T-02-05 | Denial of Service (self) | Malformed Allmaps/LUNA JSON crashing the batch mid-run | mitigate | `allmaps.lookup` (Plan 01) drops malformed per-item; rumsey worker returns `download_failed` status instead of raising — one bad map cannot abort the batch |
| T-02-06 | Tampering | Decompression-bomb JPEG from a hostile IIIF server | accept | Source is the curated David Rumsey IIIF surface (not arbitrary user upload); Content-Length ceiling (T-02-04) bounds the practical blast radius; Pillow's default `MAX_IMAGE_PIXELS` DecompressionBombWarning remains active |
</threat_model>
