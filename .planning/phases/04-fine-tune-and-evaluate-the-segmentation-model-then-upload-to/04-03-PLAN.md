Implement per 04-RESEARCH.md Pattern 4 and 04-PATTERNS.md lines 241-328.

Resolve the log(softmax) hazard explicitly (the existing `recursive_predict`
returns softmax PROBABILITIES, not logits — `torch.log_softmax` on probabilities
is wrong). Decision: in `evaluate_joint_nll`, take the cached 12-ch prob tensor,
clamp to a small epsilon floor (`prob.clamp_min(1e-12)`) and use `torch.log`
on the already-normalised probabilities — this is numerically safe BECAUSE the
inputs are valid softmax outputs in (0,1] (NOT the log(softmax(raw_logits))
anti-pattern, which is unstable on raw logits). Document this reasoning in a
comment citing RESEARCH Pitfall: the anti-pattern is `log(softmax(logits))` on
RAW LOGITS; here the probabilities are already stable softmax outputs, so
`log(clamp(prob))` is the correct and stable form. Add a unit test (Task 2)
asserting the clamp path matches a hand-computed value.

Leaf-tile filter: `[t for t in manifest["tiles"] if t["size"] == 224]`
(RESEARCH Pitfall 7). Valid mask `(lc_gt < 9) & (topo_gt < 3)`. Reuse the
`dataset.py` label-load idiom for `_load_label` (PIL → numpy → long()).
