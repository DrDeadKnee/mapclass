<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| davidrumsey.com (untrusted) → GCS data/ | Third-party image bytes cross into our storage; untrusted content + untrusted size |
| manifest `id` string → GCS blob path | Manifest-controlled id is interpolated into a blob path (path-traversal surface) |
| huggingface.co → GCS models/ | One-time model snapshot; trusted publisher, pinned repo id |
| VM ADC → GCS | The only credential; absence must fail fast, not mid-run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Tampering / DoS | Rumsey image download → ingest_images.py | mitigate | Validate HTTP 200 + Content-Type contains `image` + byte/pixel-dimension cap + `PIL.verify()` before any GCS write; failures quarantined as a terminal status in the outcome manifest (Security Domain V5) |
| T-01-05 | DoS | Decompression bomb (oversized Rumsey scan) | mitigate | Check `Content-Length`/byte cap before full materialization and cap decoded pixel dimensions; oversized → `decode-fail` status, not an OOM crash |
| T-01-06 | Tampering | manifest `id` interpolated into GCS blob path | mitigate | Blob key is `data/<id>.jpg` against a single fixed bucket via the google-cloud-storage blob API (no shell, no local path join); ids are dataset-controlled RUMSEY~ tokens, not user input — constrained surface, GCS treats key literally |
| T-01-07 | Info disclosure / Availability | GCS ADC assumed always present | mitigate | Verify ADC fail-fast at ingest/mirror job start with a clear error message; never embed secret names in code (ADC handled by the SDK) |
| T-01-08 | Tampering | Partial/non-idempotent ingest at 1,544 scale | mitigate | Download→validate→atomic-upload; skip-if-exists-and-size>0; per-id outcome manifest; re-run converges (Pitfall F) — verified by the human checkpoint re-run |
</threat_model>
