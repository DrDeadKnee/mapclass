# Constraints

All constraints below are derived from `README.md` (classified SPEC, locked: true, high confidence). They are the de-facto technical commitments of the mapclass project until superseded by a future ADR.

---

## CONSTRAINT-product-scope

source: /home/drdreadknee/mapclass/README.md
type: nfr
status: LOCKED

The system performs dense pixel-level prediction over grand-strategy-style map imagery at regional scale (100–2000 km extent). Each pixel receives two independent labels: land cover and topography. City-plan and large-scale survey maps are out of scope.

---

## CONSTRAINT-land-cover-taxonomy

source: /home/drdreadknee/mapclass/README.md
type: schema
status: LOCKED

Land cover uses a 9-class canonical taxonomy: water, trees, shrubland, grassland, cropland, built-up, bare/sparse, flooded/wetland, snow/ice.

Mapping rules from ESA WorldCover:
- ESA Mangroves fold into Trees
- ESA Moss/lichen folds into Bare/sparse

Synthetic-map taxonomy mapping (from Azgaar biomes): cropland, built-up, and flooded/wetland are not produced by synthetic maps and must be sourced from satellite imagery (up-weighted in training).

---

## CONSTRAINT-topography-taxonomy

source: /home/drdreadknee/mapclass/README.md
type: schema
status: LOCKED

Topography uses a 3-class taxonomy derived from slope thresholds on Copernicus DEM GLO-30:
- flat: slope < 2 degrees
- hilly: slope 2–15 degrees
- mountainous: slope > 15 degrees

For synthetic maps generated by Azgaar: raw height `h ∈ [20, 100]` is re-normalised to `[0, 100]` before applying thresholds (flat ≤ 20, hilly 20–55, mountainous > 55). Calibration of these synthetic thresholds against SRTM statistics is deferred.

## CONSTRAINT-data-sources

source: /home/drdreadknee/mapclass/README.md
type: api-contract
status: LOCKED

Ground-truth label sources:
- ESA WorldCover: fetched directly from `s3://esa-worldcover` (no Google Earth Engine dependency)
- Copernicus DEM GLO-30: fetched directly from `s3://copernicus-dem-30m`
- Dynamic World (GEE): optional secondary land-cover source for temporal diversity

Historical map source: David Rumsey Map Collection, accessed programmatically via the LUNA API (`scripts/build_historical_dataset.py search`). Coverage restricted to regional-scale maps (100–2000 km extent).

## CONSTRAINT-paligemma-finetuning

source: /home/drdreadknee/mapclass/README.md
type: protocol
status: LOCKED

Phase 1 fine-tunes PaliGemma-3B (SigLIP vision encoder + Gemma language model) under the following rules:
- Gemma language model is completely frozen — base weights and LoRA parameters
- LoRA adapters are applied ONLY to SigLIP attention layers: `q_proj`, `k_proj`, `v_proj`, `out_proj`
- The multi-modal projector is fully trainable
- Rationale: guarantees zero forgetting of text understanding so place names and geographic terminology remain preserved at inference time

Training data lives in `data/toons/` (~120 hex tile PNGs across 9 land cover and 3 topography classes), augmented into four visual styles (original, grayscale, parchment/sepia, faded), tiled into 2×2 region composites, and paired with five natural-language prompt templates (~4,760 samples total). Execution entrypoint: `scripts/finetune_paligemma.py`.

## CONSTRAINT-georeferencing-pipeline

source: /home/drdreadknee/mapclass/README.md
type: protocol
status: LOCKED

Historical-map georeferencing precedence:
1. Maps already registered in Allmaps/Georeferencer are downloaded automatically.
2. Unregistered maps are emitted to `unregistered_manifest.json`.
3. Semi-automatic georeferencing (depends on Phase 1 completion): fine-tuned PaliGemma generates dense terrain predictions on the unregistered map; predictions are matched against a WorldCover + Copernicus DEM reference grid via cross-correlation (rigid alignment), then refined with thin-plate spline warping (local distortion). Coastlines, mountain ranges, and major water bodies serve as anchor features.
4. Fallback: manual GCP placement via MapWarper or QGIS.

Output format: warped GeoTIFF in EPSG:4326.

## CONSTRAINT-class-conditional-loss-weights

source: /home/drdreadknee/mapclass/README.md
type: protocol
status: LOCKED

Historical-map labels are applied with class-conditional per-source loss weights reflecting temporal reliability:
- Fully trusted: topography (flat / hilly / mountainous) — geology is stable
- Mostly trusted at regional scale: water / coastlines
- Reliable: bare/sparse, snow/ice
- Heavily downweighted: trees, built-up, cropland — land use has shifted substantially since the 16th–17th century

Per-map weights are persisted in `sample_weights.json` alongside `image.png`, `land_cover.png`, and `topography.png`.

## CONSTRAINT-segmentation-backbone

source: /home/drdreadknee/mapclass/README.md
type: protocol
status: LOCKED (primary path); benchmark alternatives non-locked

Phase 3 dense semantic segmentation:
- Primary backbone: the SigLIP vision encoder from PaliGemma fine-tuned in Phase 1 (LoRA-adapted weights reused).
- Two lightweight output heads: land cover (9-class) and topography (3-class).
- Coarse-to-fine inference: implementable as a multi-resolution sliding window on SigLIP/DINOv2, or natively via Swin.
- Benchmark alternatives (non-locked): DINOv2 (self-supervised ViT), Swin Transformer (hierarchical ViT).
- Stretch goal: large first-kernel ConvNet trained from scratch — see `notes/architectural_references.md` for citations.

## CONSTRAINT-evaluation-metric

source: /home/drdreadknee/mapclass/README.md
type: protocol
status: LOCKED

Phase 4 evaluation:
- Test set: held-out synthetic maps generated by the same Azgaar + Pillow pipeline used for training but unseen during training.
- Metric: joint per-pixel negative log-likelihood — `-(log p_land_cover + log p_topography)` averaged over pixels.
- Rationale: land cover and topography are not statistically orthogonal (e.g. water is always flat, cropland is rarely mountainous), so a joint metric is more appropriate than evaluating heads independently.
- Hand-annotation of real grand-strategy map imagery is deferred. Label Studio and CVAT are candidate annotation tools if a real-domain test set is added later.

## CONSTRAINT-deliverable

source: /home/drdreadknee/mapclass/README.md
type: nfr
status: LOCKED

The fine-tuned segmentation model is uploaded to HuggingFace as the project's final deliverable. Pixel-level predictions are designed to support downstream region-delineation tooling (polygonisation of contiguous same-class areas), which is the responsibility of a separate project.

## CONSTRAINT-phasing

source: /home/drdreadknee/mapclass/README.md
type: protocol
status: LOCKED

The project progresses through four sequenced phases; PaliGemma-3B threads through all of them:
1. Fine-tune PaliGemma-3B on illustrated map terrain symbols (see CONSTRAINT-paligemma-finetuning).
2. Build a dataset of pixel-label pairs from three source families: historical illustrated maps, synthetic illustrated maps (Azgaar + Pillow), and satellite-derived imagery (ESA WorldCover + Copernicus DEM).
3. Build a dense semantic segmentation pipeline using the Phase-1 SigLIP encoder (see CONSTRAINT-segmentation-backbone).
4. Fine-tune and evaluate the segmentation model, then upload to HuggingFace (see CONSTRAINT-evaluation-metric, CONSTRAINT-deliverable).

Dependency note: Phase 2's semi-automatic georeferencing of unregistered historical maps consumes the Phase-1 fine-tuned PaliGemma. Phase 3's segmentation backbone reuses the Phase-1 LoRA-adapted SigLIP weights.
