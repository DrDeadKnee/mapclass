# Phase quick-260519-2v4 Plan 01: Multi-Model × Multi-Map dynamic-LRP Notebook Summary

One notebook runs dynamic-LRP attribution for SigLIP-2, CLIP, ViT-b-16, and
PaliGemma-3B against the last 50 Rumsey maps via a plain per-model registry,
rendering D-09 signed overlays grouped per map with captioned "no heatmap"
tiles for failures, completing headless at exit 0 — with an honest result:
**only ViT-b-16 produces real heatmaps (19/50); the other three are recorded
op-coverage / OOM "no heatmap" results.**

## What Was Built

- **`src/mapclass/models.py`** — `MODEL_REGISTRY`, a plain `dict[str, dict]`
  (no Protocol / dataclass / conformance framework). Four entries
  (`siglip2`, `clip`, `vit_b16`, `paligemma`) each exposing `load_fn`
  (cache-first GCS download, no HF at runtime), `build_inputs_fn` (returns the
  SAME requires_grad pixel tensor object — ATTR-01 identity), `target_fn`

  unchanged (27×27); D-09 invariant preserved exactly (signed = channel-sum,
  no `.abs()`, no min-max; magnitude ≥ 0). Token-shaped CLS-strip branch
  added but unused by the real pixel-space path.
- **`attribution.attribute`** generalized to
  `(model, forward_inputs, img_tensor, target_fn)` with a v1.0
  legacy-signature shim. SigLIP-2 RuntimeError finding preserved.
- **`mirror_model`** generalized to `(repo_id, gcs_dir, local_dir, token)`;
  `__main__` mirrors `openai/clip-vit-large-patch14` +
  `google/vit-base-patch16-224` (both non-gated). No PaliGemma/HF-token step.

  **`notebooks/02_multimodel.ipynb`** (committed executed artifact).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] dynamicLRP retained-activation-graph leak on the failure path**
- **Found during:** Task 3 (first headless execution — CLIP & PaliGemma OOM'd at load with 0/50 for ALL models, the wrong outcome).
- **Issue:** v1.0 `attribute()` only called `empty_cache()` on the success path. dynamicLRP (`no_recompile=True` + Promise system) retains the full forward-activation graph; on the SigLIP-2 `split_with_sizes` failure path the graph (~2.3 GB/call) was never freed, accumulating across the 50-map loop and OOM'ing every model after the first.
- **Fix:** Wrapped the forward+engine region in `try/finally`; the retained graph (`output`/`engine`/`param_vals`/`target0`) is dropped and `gc.collect()`+`empty_cache()` run in EVERY exit path; the returned relevance is `detach().clone()`-d off the graph so it cannot keep it alive.
- **Files modified:** `src/mapclass/attribution.py`
- **Commit:** `14fd238`

**2. [Rule 1 — Bug] Bound the vendored-engine leak the loader cannot reclaim**
- **Found during:** Task 3 (after fix #1, ~5.4 GB still orphaned per failing model — dynamicLRP forward hooks are not torn down on its internal failure path; the engine is FROZEN, VENDOR_SHA must not change).
- **Issue:** A per-model op-coverage gap is deterministic across maps (same architecture/op), so calling a known-failing model 50× leaks 50× for no new information.
- **Fix:** In the notebook loop, after a model's FIRST map fails, the remaining 49 maps are recorded with the SAME honest reason WITHOUT re-invoking the leaking engine; aggressive per-model teardown (`model.to('cpu')` + triple gc + `reset_peak_memory_stats`). This is NOT engineering around the gap (no Promise/LXT/captum) — all 50 tiles are still captioned "no heatmap"; it only avoids redundant leaking calls.
- **Files modified:** `notebooks/_build_02_multimodel.py`
- **Commit:** `14fd238`

**3. [Rule 3 — Blocking] `run_mirror_model.py` broken by the generalized signature**
- **Found during:** Task 2 (generalizing `mirror_model()` to require `(repo_id, gcs_dir)` broke the existing v1.0 no-arg SigLIP-2 runner).
- **Fix:** `run_mirror_model.py` now passes `config.MODEL_REPO_ID`/`config.MODEL_GCS_DIR` explicitly (`token=None`), preserving its original SigLIP-2 purpose.
- **Files modified:** `notebooks/scripts/run_mirror_model.py`
- **Commit:** `a40a33f`
